Most personal sites are museums — walk the halls, nothing talks back.

An **agent-native** site inverts that: conversation over a content registry you
control. Keep chrome minimal. Let blogs and announcements grow as data, not as
new UI every time.

## Design constraints

1. One primary surface (here: the terminal)
2. Content is a typed registry — MDX in git for now
3. Routes only change **boot state**, not the interaction model

```ts
type TerminalBoot =
  | { mode: "home" }
  | { mode: "blogs" }
  | { mode: "blog"; slug: string };
```
